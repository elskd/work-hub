# Work Hub · задачи и CRM

Личная рабочая система: адаптивная Главная, задачи, план дня, клиенты, проекты и поиск клиентов.

## Запуск

Нужны Node.js 20+ и Python 3. Интерфейс не требует сборки или внешних сервисов.

```sh
npm ci
npm start
```

Откройте `http://127.0.0.1:4173` **на том же компьютере**. URL не открывает облачный предпросмотр на телефоне. Для модулей и безопасного локального сохранения используйте HTTP localhost или HTTPS, не `file://`.

## Что работает

- Шесть блоков Главной: задачи, расписание, сроки задач/проектов, проекты, месячная выручка, объяснимый следующий шаг.
- Создание/редактирование/выполнение/возврат/архивирование/удаление задач, подзадачи, приоритеты, независимые дедлайн и расписание, поиск и фильтры.
- Ежедневные, еженедельные и ежемесячные повторения, интервалы и дни недели; один экземпляр или будущая серия. Повтор не размножается после повторного выполнения.
- Светлая, тёмная, системная тема; чёрный, бордовый, зелёный акцент.
- Подтверждённое локальное сохранение, обнаружение конфликтов вкладок, ошибки без потери открытой формы, экспорт JSON.

- Клиенты с контактами и несколькими проектами; поиск и архив без удаления связей.
- Проекты: четыре услуги, редактируемые этапы, отдельные статусы, список/доска, сроки и связанные задачи.
- Потенциальные клиенты: контакты, источник, статусы, фильтры, следующий контакт и задача в расписании. Перевод в клиента/проект сохраняет прогресс, предлагает существующего клиента при совпадении контактов и не создаёт фиктивную оплату.

## Границы этого этапа

Данные сохраняются **только в текущем браузере**. Вход, сервер, синхронизация телефона с Mac и восстановление JSON ещё не реализованы. Очистка данных браузера удалит записи; экспортируйте резервные копии. Для безопасного сохранения нескольких вкладок нужен браузер с Web Locks API. Отсутствие API даёт явную ошибку без ложного сообщения об успехе.

Деньги и платежи через интерфейс, документы, файлы, настраиваемый список статусов лидов, контент, дизайн, материалы, калькулятор и ИИ остаются следующими этапами. В рабочую базу демонстрационные записи не добавляются.

Обновление CRM добавляет отсутствующие коллекции без записи при открытии. Перед первым сохранением обновлённой базы исходные данные целиком сохраняются в локальный ключ `workhub.stage1.v1.before-crm`; существующая резервная копия не перезаписывается. Ошибка создания копии блокирует основную запись. Эта копия находится в том же браузере и не заменяет внешний JSON-экспорт.

Полный объём утверждённого ТЗ, включая обязательную синхронизацию, остаётся дальнейшей работой. Это не окончательная рабочая версия.

## Проверки

```sh
npm test
npm run test:browser
# Свой Chromium/Chrome:
CHROMIUM_PATH=/path/to/chromium npm run test:browser
```

Браузерный тест использует изолированные профили и тестовые записи, запускает локальный сервер, фиксирует дату и часовой пояс. Проверяет 320/390/768/1024/1440 px, формы, меню, темы, длинный русский текст, реальные изменения задач и перезагрузку, ошибки сохранения, связи с проектом/поступления, повторения и конфликт вкладок. Скриншоты и машиночитаемый результат создаются в `test-results/` (не включаются в Git).

Cloud QA: Chromium 154.0.8037.57. Safari на Mac/iPhone и настоящая экранная клавиатура телефона не проверены в облаке.

## Архитектура и публикация

`src/domain.js` и `src/crm-domain.js` — чистые правила и расчёты; `src/store.js` — заменяемый адаптер хранения; `src/app.js` и `src/crm-ui.js` — интерфейс; `src/styles.css` — общие компоненты/токены. Реальные записи и секреты не хранятся в Git.

Разработка идёт в `feature/work-hub-stage-2`. Основная ветка автоматически публикует GitHub Pages: не обновляйте main без отдельного согласования публикации. Каталог `marketing-girl/` и существующий workflow не изменены.
